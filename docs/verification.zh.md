## 安装后的 Harness Session 证据

`scripts/verify-harness.mjs` 通过 `dsh plugin` 将安装包加入临时配置，使用官方脚本化回放提供器执行六次普通 Session 工具，解析实际 JSON 制品，断言修订 2 和指定文字替换，再卸载重装并确认数据保留，禁用 Host/工具后断言模型不再看到简历工具，重新启用后读取保留的修订。该流程在禁止读取两个原项目时通过。脚本化回放用于确定性集成验证，与下文真实模型运行分别记录。

将 `DSH_TEST_CLI` 指向安装的 `@deepseek-ai/dsh/lib/bin.js`，将 `DSH_TEST_REPLAY` 指向同版本回放提供器的 `lib/index.js`，并传入安装包路径。仅在缓存完整时追加 `--offline`，脚本不使用模型凭据。Harness 共享服务保持 peer 声明，由运行时安装锚点提供唯一实例。

`scripts/verify-recorded-session.mjs` 安装包并重放真实 Session `session-85af7729-f1e0-4b91-a7d3-c048e4286955` 的第一轮，使用官方格式读取器及录制的助手流。两次调用执行实际 `resume_read`，选中保存的图片，隐藏内嵌字节，以 `LIVE_RESUME_REPLAY_OK` 结束。无模型凭据断言归属此包的预期投影及未改变的合成种子，与脚本化集成分别记录。
